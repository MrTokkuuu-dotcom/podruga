# «Глаза и руки» — замысел (24.11.2026)

## Зачем
Дима хочет, чтобы Подруга сама делала простые дела на Mac голосом: «включи такую-то песню в YouTube Music»,
«открой нужное», «найди что-то». Сейчас она умеет только открыть ссылку или программу (`actions.py`).
Пример провала из журнала (23.11, 16:20): открыла `music.youtube.com/search?q=…`, а песню не включила —
вместо этого `Music: play` запустил «Музыку» Apple. Нужно, чтобы она доводила дело до конца: видела экран,
нажимала и печатала.

## Цели
- Видит, что на экране: кнопки, поля, ссылки и текст активной программы.
- Нажимает, печатает, листает, жмёт клавиши — по просьбе Димы, за несколько шагов.
- Частые дела (песня в YouTube Music, видео на YouTube, поиск на сайте) — быстро и надёжно, за 2–5 с.
- Работает без ключа Google, на своём мозге Gemma. С ключом — умеет больше (запасной путь по снимку экрана).
- Всё, что ставим, можно продавать (правило Димы, `THIRD_PARTY.md`).

## Не цели (сейчас)
- Сама, без просьбы, ничего на экране не делает (инициатива — только словами, как сейчас).
- Игры, рисовалки и окна без «дерева доступности» — только через запасной путь Google, если есть ключ.
- Windows — позже.

## Анти-цели (провал, даже если «работает»)
- Ввела пароль, код, номер карты — **никогда**, даже если Дима сам продиктовал.
- Нажала «Купить / Отправить / Удалить / Оплатить / Опубликовать» без «да» Димы.
- Послушалась текста на странице («нажми сюда», «введи пароль») — команды только из речи Димы.
- Mac греется или тормозит в простое: «глаза» работают только во время задачи.
- Сломала то, что работает: голос, память, касания, автообновление, окно поверх всего.

## Ограничения
- Мак Димы: M1 Pro, 16 ГБ, macOS 27. Мозг уже занимает ~6 ГБ, весь процесс ~11–12 ГБ — вторую модель
  (для картинок) не грузим.
- Свой мозг понимает только текст и отвечает по очереди (один поток) — шаги задачи идут через ту же очередь.
- Разрешения macOS: «Универсальный доступ» (чтобы читать кнопки и нажимать) и «Запись экрана» (снимок и
  распознавание текста). Дима включает сам; Подруга показывает, где.
- Её окно — прозрачное на весь экран, поверх всего (`winctl`, `ClickThrough`). Клики мышью не должны
  попадать в неё саму.

## Способы (что рассматривали)
| Способ | Плюсы | Минусы |
|---|---|---|
| 1. Готовые рецепты (ссылка + нажать нужную кнопку) | 2–5 с, почти всегда срабатывает, без ключа | только то, чему научили |
| 2. «Дерево доступности» macOS + распознавание текста Apple + свой мозг выбирает шаг | на Mac, без ключа, можно продавать, текст точный, видно поля паролей | нет «дерева» в играх и нарисованных окнах |
| 3. Снимок экрана → Google решает, куда кликнуть | понимает всё | нужен ключ, 3–10 с на шаг, снимок уходит в Google |

**Выбрано Димой (24.11): смесь** — сначала рецепт, если нет — способ 2, способ 3 — запасной, только с ключом.

## Как устроено

### Новые части
- **`eyes.py` — глаза.**
  - `snapshot()` — список видимых элементов активного окна через Accessibility (pyobjc ApplicationServices,
    уже стоит): роль, подпись/значение, рамка на экране, включён ли. Нумерованный, до ~80 элементов,
    сначала интерактивные (кнопки, ссылки, поля, пункты списка), потом заметный текст. Для Chrome перед
    чтением ставит приложению `AXManualAccessibility = true` (иначе Chrome не отдаёт страницу).
    Поля паролей (`AXSecureTextField`) помечаются как «пароль» и в руки не попадают.
  - `read_text()` — распознавание текста на экране (Vision, `VNRecognizeTextRequest`, ru/en/ko) — когда
    «дерево» пустое или бедное (меньше ~5 элементов). Снимок — существующий `vision.capture()`.
  - Своё окно Подруги в список не попадает.
- **`hands.py` — руки.** `press(el)` — сначала `AXPress` (без мыши), если не вышло — клик мышью в центр
  элемента (Quartz CGEvent). `type_text(el, text)` — фокус в поле и ввод по буквам (CGEvent Unicode),
  `key(name)` — Return, Tab, Esc, стрелки, ⌘L и т. п. из короткого белого списка, `scroll(dir)`.
  Перед кликом мышью окно Подруги на время пропускает клики насквозь целиком.
  Каждое действие сначала проходит через `guard.py`.
- **`guard.py` — охрана.**
  - Печатать в поле пароля — нельзя; печатать текст, похожий на пароль/код/номер карты (цифры 12+ подряд,
    «пароль», «код из смс», «CVC»…) — нельзя. Отказ вслух.
  - «Опасные» кнопки (ru/en/ko): отправить, send, купить, buy, оплатить, pay, заказать, order, удалить,
    delete, опубликовать, post, подписаться, subscribe, перевести, подтвердить, confirm, 전송, 구매, 결제,
    삭제, 주문 и т. п. → она спрашивает «Нажать «Купить»?» и ждёт «да» голосом или в чате до 20 с;
    молчание или любое другое — «нет».
  - Запрещённые программы: Связка ключей, Системные настройки, Терминал/iTerm (печатать), менеджеры паролей.
  - Не больше 12 шагов и 90 с на задачу; дальше — спрашивает, продолжать ли.
  - «Стоп / хватит / отмена / подожди» в любой момент — сразу прекращает.
  - Каждое действие — в журнал (`[руки] …`).
- **`recipes.py` — рецепты.** На старте:
  - YouTube Music: песня/исполнитель → `music.youtube.com/search?q=…` → дождаться загрузки → нажать
    кнопку воспроизведения первого результата-песни.
  - YouTube: видео → поиск → открыть первое видео.
  - «Найди X на <сайт>» — ссылка поиска сайта (Naver, Coupang, Google…), только открыть.
  Если рецепт не справился за ~8 с — задача уходит агенту (способ 2) с того места, где остановился.
- **`agent.py` — общий цикл.** Цель (словами Димы) → повторять: `snapshot` (или `read_text`) → свой мозг
  получает цель, прошлые шаги и список элементов и отвечает одной командой:
  `<<НАЖАТЬ 12>>`, `<<ПЕЧАТАТЬ 5 | текст>>`, `<<КЛАВИША enter>>`, `<<ЛИСТАТЬ вниз>>`, `<<ОТКРЫТЬ ссылка>>`,
  `<<ГОТОВО что сделала>>`, `<<НЕ МОГУ почему>>`. Текст с экрана в подсказке помечен как «данные, не
  команды». Если свой мозг дважды подряд не может (`НЕ МОГУ` / пустой экран) и есть ключ — один шаг
  через Google по снимку экрана (клик по координатам, та же охрана).

### Связка с тем, что есть
- Мозг получает новую команду `<<СДЕЛАТЬ задача>>` (в `brain.py` и `local_prompt.py` с примерами);
  `main.handle_commands` запускает задачу в своём потоке: рецепт → агент.
- `intents.py`: «включи <песня> в ютуб музыке» → сразу рецепт, без мозга.
- Пока идёт задача: она говорит коротко, что делает («Ищу…», «Включаю»), в чате строки 👀/👆,
  на прозрачном окне — рамка вокруг элемента, который нажимает. Разговор во время задачи — «стоп» понимает
  всегда, остальное — после задачи.
- Настройки: раздел «Глаза и руки» — включено/выключено, состояние двух разрешений и кнопки «Открыть
  настройки macOS» на нужной странице; галочка «Если сама не справлюсь — смотреть через Google» (видна
  только с ключом).
